# ADR-0001：客户内网 Worker 执行架构

- 状态：**已采纳为下一阶段目标架构**
- 决策范围：企业部署拓扑、Worker 通信边界、人工临时凭证管理
- 当前实现状态：**尚未实现**。本 ADR 是设计决策，不代表当前仓库已经支持远程 Worker、远程 MCP 或生产级凭证管理。

## 背景

部分客户通过堡垒机人工申请数据库临时连接串，连接串有效期约 8 小时。堡垒机目前没有可供 SafeDB 调用的自动申请/续期 API，因此不能依赖程序自动轮换凭证，也不应要求管理员频繁修改数据源 YAML 或重启服务。

企业数据库通常位于客户内网，不应为了使用 SafeDB 而向 SaaS 云端开放数据库入站访问。

## 决策

采用 **云端控制面 + 客户内网执行面（C1）** 作为企业部署的默认目标架构：

- 云端：远程 MCP Gateway、身份认证、API、租户/数据源授权、提案与审批、任务调度和审计索引。
- 客户内网：独立部署的 SafeDB Worker、数据库凭证提供/存储组件、数据库连接池和 SQL 执行。
- Worker 主动通过 TLS 保护的出站 HTTPS 通道连接云端领取任务和回传状态/受限结果；云端不得主动连接客户 Worker，也不得直接连接客户数据库。
- Worker 必须具有独立、可撤销、绑定租户和部署环境的工作负载身份。生产实现采用 mTLS 或等价的强双向身份认证，不使用共享静态 Worker Token 作为最终方案。
- Worker 不直接连接暴露在公网的控制面 PostgreSQL。云端 PostgreSQL 保持私有，仅由云端 API/调度服务访问；Worker 使用受限的任务协议。
- 每个客户/信任域使用独立 Worker 实例或强隔离的 Worker 池，不允许不同租户共享数据库凭证、连接池或进程内秘密状态。

## C1 的数据边界

C1 把数据库凭证和 SQL 执行留在客户环境，但**不代表查询数据完全不经过云端**。按照默认任务流程，SQL、必要的参数、执行状态和受限查询结果可能经过 SafeDB 云端。

- 客户必须明确批准允许发送到云端的 SQL、参数、结果字段、行数和字节上限。
- 云端结果存储必须有加密、租户隔离、访问控制、保留期限和删除策略。
- 不允许将“数据库在客户内网执行”宣传为“数据从不离开客户网络”。
- 对禁止查询结果离开客户网络的场景，后续设计 C2（结果在本地脱敏/聚合）或 C3（完整客户私有化部署）。

## 人工临时凭证流程

堡垒机没有自动化 API 时，凭证刷新是一个**人工触发、系统安全应用**的流程：

1. 客户管理员登录现有堡垒机，按客户既有流程人工申请临时连接串。
2. 管理员在客户内网 Worker 主机上，通过本地管理 CLI 或客户内网受控管理入口提交连接串。此操作不得经过云端 MCP、云端 API 或 Agent 工具。
3. 凭证管理组件验证数据源绑定、格式和管理员权限，并记录操作人、数据源、凭证版本、录入时间、有效期和操作结果；审计记录不得包含连接串、密码或令牌。
4. Worker 对新凭证进行有界、只读的连接验证。验证成功后原子切换到新凭证，并逐步淘汰旧连接池；验证失败则保留当前有效凭证并报告失败。
5. Worker 根据堡垒机给出的到期时间执行到期管理。建议在到期前进入 EXPIRING 状态并通知管理员；到期后进入 NEEDS_CREDENTIAL，停止该数据源的新任务。
6. 管理员再次人工申请并录入新凭证后，Worker 完成验证和连接池切换，恢复接收该数据源任务。

**YAML 只保存非敏感数据源元数据和策略**，例如 datasource ID、数据库方言、允许的 schema/table、行数/字节/时间上限、凭证提供方类型和本地 secret profile 标识。临时连接串、密码、访问令牌不得写入 YAML、Git、云端配置、Agent 提示词或应用日志。

## 凭证存储原则

- 定义独立的 CredentialProvider / CredentialStore 接口，SQL Guard、查询服务和数据库适配器不直接耦合堡垒机产品。
- 优先接入客户已有 Vault、操作系统密钥存储或客户自管 KMS。
- 不具备外部密钥管理设施时，首个可控版本可以采用仅驻留进程内存的凭证模式；Worker 重启后要求管理员重新录入。不得为了跨重启保留而默认把明文连接串写入普通文件或 SQLite。
- 如未来实现本地加密持久化，解密密钥必须由独立于密文文件的客户控制密钥设施提供，且需要单独安全评审。
- 管理接口不得把凭证放在 URL、命令行参数、环境变量、shell history、HTTP 访问日志或异常堆栈中。CLI 应使用无回显交互输入；管理 API 仅绑定客户内网管理面并使用强操作人认证。
- 云端只接收凭证状态、到期时间、非敏感版本号和轮换事件，不接收凭证值或连接串。

## 到期与连接池状态

数据源凭证状态至少包括：

**MISSING → ACTIVE → EXPIRING → NEEDS_CREDENTIAL**

另有验证失败状态 INVALID。实际实现必须避免仅依赖数据库认证失败来推断到期。

- 管理员录入有效期；优先使用堡垒机明确提供的到期时间。若只能确认“录入后最长 8 小时”，则使用客户配置的保守 TTL，并从本地收到凭证的时间开始计时。
- 到期或状态不确定时 fail closed：禁止该数据源的新任务，不得反复用旧凭证重试。
- 已经执行中的查询按受限执行预算处理；若数据库端因凭证撤销而断开，按普通执行失败处理，不得使用旧凭证无限重试。
- 新凭证验证成功后创建新连接池，原子切换活动凭证版本，并关闭/淘汰旧池。连接池中的连接不得跨凭证版本复用。
- 记录凭证轮换的审计元数据，不记录秘密，也不记录可用于反推出秘密的连接 URL 指纹。

## 网络和信任边界

- 客户 Worker 只需要向明确配置的 SafeDB 云端入口发起出站 HTTPS；不对互联网开放 Worker 入站端口。
- Worker 到数据库、堡垒机和本地密钥管理服务的流量使用客户内网 ACL/防火墙控制。
- 对数据源主机、端口、DNS 解析和重定向实施出口 allowlist，防止 Worker 成为可被 Agent 操控的任意网络代理或 SSRF 跳板。
- 云端任务必须绑定 tenant、worker identity、datasource、proposal、SQL/参数摘要、策略版本、过期时间和唯一 fencing/lease 信息。Worker 执行前再次检查任务完整性、数据源归属、策略和租约。
- Worker 状态回传必须使用幂等请求和 fencing token；失去租约的旧 Worker 不能发布状态或结果。
- 客户端、云端和本地 Worker 都要有可关联的审计事件 ID，但审计日志不得收集凭证、原始敏感参数或不必要的查询结果。

## 堡垒机兼容性前置检查

方案 C 的 Worker 应运行在**能够实际访问堡垒机和目标数据库的客户内网主机**，不必是 Codex 所在电脑。

实施前必须验证人工获得的连接串是否：
- 从计划部署 Worker 的主机可路由；
- 不依赖操作者个人电脑上的 localhost 端口转发或仅存在于浏览器会话中的隧道；
- 不绑定到不可迁移的操作者 IP、设备证书或交互式桌面会话；
- 在 Worker 所用驱动、TLS 根证书和数据库版本上可用。

若连接串只在操作者电脑或个人 SSH 隧道中有效，则 Worker 必须部署在该电脑，或客户需要提供受控的内网隧道/堡垒机代理。不能假设把连接串复制到服务器就一定可用。

## 实施阶段

1. **架构与协议**：定义租户/Worker 身份、任务协议、租约、fencing、审计关联和 C1 数据流；保持云端 PostgreSQL 不对 Worker 直接暴露。
2. **本地 Worker 与凭证生命周期**：抽象凭证提供/存储接口，实现本地人工录入、有效期状态机、连接池切换、到期停单和秘密脱敏测试。
3. **云端任务调度**：将 SQLite 原型存储迁移到 PostgreSQL；实现 Worker 出站领取任务、心跳、租约恢复、状态回传和幂等结果发布。
4. **远程 MCP 与多租户身份**：实现远程 MCP 传输、OIDC/OAuth、tenant/agent/reviewer 隔离、Worker 注册和撤销。
5. **企业加固**：结果脱敏、C2 本地数据处理、不可篡改外部审计、配额/取消、网络渗透测试和灾备验证。

当前 PR 只记录架构决策和实施边界，不代表以上运行时能力已经落地。项目在完成相应代码、集成测试和安全评审前，仍保持安全原型状态。
